# ポータル試作 第6版（v6）

社内HTMLツールを1つのポータルにまとめる仕組みの試作。中身はテスト用の架空データ（名前・接続先）と、
実ツール2つ（360°Viewer、AI・DX定例会へのリンク）。

**最新かどうかの見分け方：ポータルYの見出しの横が「v6」、入口ページの見出しが「ポータル試作 第6版（v6）」。**

## 構成

```
index.html                 入口ページ（X・Y・Zの各方式へ）
sw.js                      サービスワーカー（常にサーバーに更新を確認する）
common/sanei.js            共通スクリプト（利用者名・接続先設定・インストール記録・共通インストールボタン）
common/portal.js           ポータル画面の共通処理
common/style.css           共通の見た目
icons/                     アイコン
y/portal/                  ポータルY（採用候補）
y/tools/viewer360/         360°Viewer（実ツール。元ファイルに先頭4行を追加しただけ）
y/tools/calc/, memo/       テスト用ツール
x/, z/                     比較用の方式（確認済み）
```

## 採用候補：Y方式の仕様（試作で確認済み）

- ポータルとツールを並べて置く（ツールをポータルのフォルダの中に置かない）
- アプリごとに固有のIDを manifest に書く（"./" は不可。サイトの一番上に解決されて全アプリ同一IDになる）
- 全員がインストールするのはポータル1つ。ポータルは二重に開かない（launch_handler: focus-existing）
- インストールしていないツール：ポータルから開くとポータルの小窓（上に白い帯）で開く
- インストール済みのツール：ポータルから開くとツール専用の窓で開く（launch_handler を書いたツールは
  Chromeのリンク取り込みの対象になるため）
- ツールのインストール：右下の「このツールをインストール」（共通スクリプトが自動で表示。
  インストール済みの窓では出さない）。ポータルから他のアプリを直接インストールする機能は、
  Chromeでは試験提供中のため使わない
- 名前・設定・接続先（設定リンク）は全アプリで共有
- GitHubで直すと、ほぼすぐ反映される
- ツールに「ポータルに戻る」は置かない（Chromeの仕様で他の窓を前に出せないため。タスクバーから戻る）
- タスクバーのポータルの右クリックからツールを選ぶ機能は使えない（ツールがポータルの範囲外のため）

## 版ごとの変更

- 第1〜3版：方式の比較（X・Y・Z）。全アプリのIDが同じになっていた不具合を第3版で修正
- 第4版：ポータルが二重に開かないようにした。更新がすぐ反映されるようにした（キャッシュ対策）
- 第5版：360°Viewer・AI・DX定例会を追加。インストール済みのツールは専用の窓で開く
- 第6版：インストールボタンを右下の共通ボタンに統一。インストール済みの窓ではボタンを出さない

## 公開手順

1. GitHubのリポジトリ（Public）に、このフォルダの**中身**をまとめてアップロード（上書き）
2. Settings → Pages → Branch: main / (root) → Save（設定済みなら不要）
3. 1〜2分後に開き、Ctrl＋Shift＋R で再読み込み
