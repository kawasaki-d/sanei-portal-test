# ポータル試作 第4版（X・Y・Z方式の比較）

第1版の確認で、ツールをポータルの中に置いたままツールにもアプリ設定を持たせると、
ツール単体のインストールができず、ポータルのアプリがツールに置き換わる（「ロゴと名前の更新」）ことが分かった。
第2版では、次の2方式を同じ置き場に並べて比較する。中身はすべて架空のデータ。

- X方式（x/）: ツールはポータルの中。ツール側にアプリ設定を持たせない。インストールはポータル1つ。
  タスクバーのポータルアイコンを右クリックしてツールを選べるかを確認する。
- Y方式（y/portal/, y/tools/）: ポータルとツールを並べて置き、それぞれ別アプリにする。
  ツールはインストールしなくてもポータルから使え、お気に入りだけ単体インストールできるかを確認する。

名前・設定の保存は、X・Yとも同じ置き場（同じオリジン）なので共通。
公開手順は第1版と同じ（リポジトリ名は sanei-portal-test2）。

## 第3版の修正（重要）
第2版までは manifest の "id" を "./" と書いていたため、Chromeがサイトの一番上（https://<アカウント>.github.io/）に解決し、
全アプリが同じIDになっていた。これが「ロゴと名前の更新」やインストールできない不具合の原因。
第3版では全アプリに固有のID（sanei-test/portal-x など）を付けた。
同じ github.io に複数のアプリを置く場合、**アプリごとに固有のIDを書くことが必須**。

- Z方式（z/）: ツールはポータルの中に置き、ツールにも固有IDを付けて単独インストールできるようにした版。

## 第4版の修正（Y方式）
- ポータルの「開く」を1つにし、アドレスバーの無い独立した窓で開く。同じツールが開いていればその窓を前に出す（窓が増えない）
- ツールの「ポータルに戻る」：開いたポータルの窓を前に出す。見つからなければ新しい窓は開かず案内を表示
- ポータルYのアプリ設定に launch_handler（client_mode: focus-existing）を追加。アイコンから開き直しても窓が増えない
- サービスワーカーで更新確認時にHTTPキャッシュを使わないようにした（GitHub Pagesは約10分キャッシュされるため、更新の反映が遅れていた）
